# MikroTik Wi-Fi mesh

Wi-Fi mesh із дротовим підключенням точок доступу: RB4011 є роутером і контролером CAPsMAN, а hAP ac3 та hAP ax3 — керовані точки доступу (CAP). Файли налаштувань для кожного пристрою генеруються зі спільних шаблонів і значень у `.env`.

## Швидкий старт

1. **Задайте параметри в `.env`.**
   ```
   cp .env.example .env
   ```
   Відкрийте `.env` і вкажіть пароль admin (`ADMIN_PASSWORD`), пароль Wi-Fi (`WIFI_PASSWORD`) і назву мережі (`WIFI_SSID`). Решта параметрів необов'язкові, див. [Параметри .env](#параметри-env).

   *Необов'язково:* щоб не вигадувати пароль Wi-Fi і суфікс SSID, згенеруйте їх випадково: `python3 randomize.py`. Скрипт запише в `.env` новий `WIFI_PASSWORD` (16 символів: цифри, великі й малі літери та спецсимволи) і замінить останні 4 символи `WIFI_SSID` на 4 випадкові шістнадцяткові символи, як у назвах мереж TP-Link (`Tp-Link_AD98` стане `Tp-Link_7D15`). Значення виводяться в консоль, їх треба буде ввести клієнтам. З параметром `--admin-password` випадковим стане і `ADMIN_PASSWORD`, а `--password-length N` задає довжину паролів. Див. [Випадкові значення Wi-Fi](#випадкові-значення-wi-fi).

2. **Згенеруйте файли налаштувань** (потрібен Python 3, інших залежностей немає):
   ```
   python3 generate.py
   ```
   У каталозі `generated/` з'являться 5 файлів: `rb4011.rsc`, `ac3-1.rsc`, `ac3-2.rsc`, `ax3-1.rsc`, `ax3-2.rsc`.

   За замовчуванням створюється **одна Wi-Fi мережа** для обох діапазонів (2.4 і 5 ГГц), клієнт сам обирає діапазон. Якщо потрібні окремі мережі, додайте `--show-separate`, див. [Одна чи дві мережі](#одна-чи-дві-мережі). Діапазон адрес DHCP (за замовчуванням `.20`-`.254`) змінюється через `--lease-range`, див. [Діапазон адрес DHCP](#діапазон-адрес-dhcp).

3. **Підготуйте пакети Wi-Fi на пристроях.** Усі пристрої мають працювати на одній версії RouterOS (перевірено на 7.24.5). Стан пакетів дивіться командою `/system package print`.

   | Пристрій | Пакет | Що зробити |
   |---|---|---|
   | RB4011 | `wifi-qcom-ac` | Пакет вже є в прошивці. Якщо він позначений `X` (вимкнений): `/system package enable wifi-qcom-ac`, потім `/system reboot`. |
   | hAP ac3 | `wifi-qcom-ac` | 1. Завантажте з [mikrotik.com/download](https://mikrotik.com/download) архів Extra packages для ARM тієї ж версії, що й RouterOS на пристрої, і розпакуйте з нього `wifi-qcom-ac-<версія>-arm.npk`. 2. Завантажте файл на роутер (WinBox: Files, перетягнути). 3. `/system reboot`. 4. Після перезавантаження: `/system package print`. Якщо пакет вимкнений, виконайте `/system package enable wifi-qcom-ac`. Якщо є пакет `wireless`, видаліть його: `/system package uninstall wireless`. 5. `/system reboot` ще раз. |
   | hAP ax3 | `wifi-qcom` | Див. [Пакет Wi-Fi для hAP ax3](#пакет-wi-fi-для-hap-ax3). Спочатку перевірте `/system package print`: якщо `wifi-qcom` вже є й увімкнений, більше нічого робити не треба. |

4. **Збережіть резервну копію поточної конфігурації** кожного пристрою перед скиданням (скидання з `skip-backup=yes` нічого не зберігає). Виконайте на пристрої, підставивши його ім'я:
   ```
   /export show-sensitive file=backup-rb4011
   ```
   Для точок доступу `backup-ac3-1`, `backup-ax3-2` тощо. Файл `backup-<ім'я>.rsc` з'явиться в Files: завантажте його на комп'ютер (WinBox: Files, перетягнути; або `scp admin@<адреса>:backup-rb4011.rsc backups/`). **Файл містить паролі у відкритому вигляді**, тому тримайте його в каталозі `backups/` (він у `.gitignore`). Детальніше: [Резервна копія](#резервна-копія).

5. **Застосуйте налаштування.** Спочатку на RB4011, потім на точках доступу. Для кожного пристрою: завантажте його файл із `generated/` на роутер і виконайте
   ```
   /system reset-configuration no-defaults=yes skip-backup=yes run-after-reset=rb4011.rsc
   ```
   Для точок доступу вкажіть їхній файл, наприклад `run-after-reset=ac3-1.rsc` або `run-after-reset=ax3-2.rsc`. Детальніше: [Застосування файлів](#застосування-файлів).

6. **Перевірте результат:** [Перевірка](#перевірка).

## Мережа

- LAN `192.168.89.0/24`, роутер `192.168.89.1`, пул DHCP за замовчуванням `.20`-`.254` (235 адрес), змінюється параметром `--lease-range`, див. [Діапазон адрес DHCP](#діапазон-адрес-dhcp).
- `ether1` на RB4011 — це WAN (DHCP-клієнт). Усі інші порти об'єднані в LAN-міст.
- SSID: за замовчуванням одна мережа з назвою `WIFI_SSID` для обох діапазонів. З `--show-separate`: `WIFI_SSID` для 2.4 ГГц і `WIFI_SSID-5g` для 5 ГГц. WPA2/WPA3-PSK, увімкнений роумінг 802.11r/k/v.
- Кожна точка доступу підключається кабелем до LAN-порту RB4011 (або до комутатора, що веде до нього), отримує адресу керування по DHCP і приєднується до CAPsMAN через міст.
- Імена пристроїв (identity) унікальні в межах мережі: `rb4011`, `ac3-1`, `ac3-2`, `ax3-1`, `ax3-2`.

## Мінімальний рівень сигналу

Клієнти самі вирішують, коли перейти на іншу точку, і часто тримаються за слабку до −80 дБм і гірше. Параметр `MIN_SIGNAL` у `.env` (за замовчуванням `-80`) додає на RB4011 правило `/interface wifi access-list` з `action=reject` і `signal-range=-120..<MIN_SIGNAL>`: клієнти слабші за поріг відхиляються й шукають сильнішу точку. Правило поширюється CAPsMAN на всі точки та діє на власне радіо RB4011.

- `MIN_SIGNAL=off` вимикає правило. Значення поза діапазоном `-100`...`-50` генератор відхиляє.
- Не ставте поріг надто високим: клієнт на краю покриття єдиної точки не зможе підключитися взагалі.
- Чи відключається вже підключений слабкий клієнт, чи лише не пускається новий, залежить від версії RouterOS; перевіряйте через `python3 traffic.py --show-zeros` (колонка «Сигнал»).
- Змінити або скасувати правило на працюючому роутері без повного застосування файлу:
  ```
  /interface wifi access-list add action=reject signal-range=-120..-80 comment=min-signal
  /interface wifi access-list remove [find comment="min-signal"]
  ```
  Щоб зміна не зникла при наступному застосуванні файлу, змініть також `MIN_SIGNAL` у `.env` і перегенеруйте файли.

## Діапазон адрес DHCP

Параметр `--lease-range` у `generate.py` задає діапазон адрес, які RB4011 видає клієнтам (і точкам доступу, бо вони теж отримують адресу по DHCP). Значення це останні октети адрес підмережі `192.168.89.0/24`:

```
python3 generate.py                          # 20-254 за замовчуванням: 192.168.89.20-192.168.89.254 (235 адрес)
python3 generate.py --lease-range 100-254    # 192.168.89.100-192.168.89.254 (155 адрес, як було раніше)
python3 generate.py --lease-range 20-154     # 192.168.89.20-192.168.89.154 (135 адрес)
```

- Межі від 2 до 254: `.1` займає роутер, `.0` і `.255` службові. Початок не може бути більшим за кінець.
- Адреси поза діапазоном (`.2`-`.19` за замовчуванням) лишаються вільними для пристроїв зі статичними адресами.
- Змінюється лише файл RB4011. Після зміни діапазону його треба застосувати заново. Якщо скидати роутер не хочеться, можна змінити пул на ходу: `/ip pool set pool-lan ranges=192.168.89.20-192.168.89.254`. Вже видані адреси при цьому лишаються чинними до закінчення оренди (1 година).
- Скрипт друкує підсумок, наприклад `DHCP: 192.168.89.20-192.168.89.254 (235 адрес)`.

## Одна чи дві мережі

Параметр `--show-separate` у `generate.py` визначає, скільки Wi-Fi мереж побачать користувачі:

```
python3 generate.py                          # одна мережа (за замовчуванням)
python3 generate.py --show-separate          # дві мережі: SSID і SSID-5g
python3 generate.py --show-separate false    # те саме, що без параметра
```

Допустимі значення `true`/`false` (також `yes`/`no`, `1`/`0`). Без значення `--show-separate` означає `true`. Змінюється лише конфігурація на RB4011 ([rb4011.rsc](generated/rb4011.rsc)); файли точок доступу від цього параметра не залежать.

| | Одна мережа (за замовчуванням) | `--show-separate` |
|---|---|---|
| Назви | `WIFI_SSID` | `WIFI_SSID` (2.4 ГГц) і `WIFI_SSID-5g` (5 ГГц) |
| Вибір діапазону | Клієнт сам, зазвичай віддає перевагу 5 ГГц | Користувач вручну вибирає мережу |
| Конфігурація CAPsMAN | `cfg-2g` і `cfg-5g` з однаковим SSID | `cfg-2g` і `cfg-5g` з різними SSID |

Що слід знати про одну мережу:
- MikroTik не вміє примусово переносити клієнта на 5 ГГц. Увімкнені 802.11k/v (`steering.rrm`, `steering.wnm`) лише підказують клієнтам, а рішення приймає пристрій. Сучасні телефони й ноутбуки зазвичай обирають 5 ГГц, якщо сигнал достатній, але гарантії немає. Наскільки добре ваші клієнти слухаються підказок, я не перевіряв.
- Деякі старі пристрої на 2.4 ГГц (розумні розетки, лампи, принтери) погано працюють із WPA3 і швидким роумінгом 802.11r, які увімкнені в конфігурації. Якщо такий пристрій не підключається до єдиної мережі, або вимкніть для нього ці режими, або створіть окремі мережі через `--show-separate`.
- Роумінг між точками в межах одного діапазону працює однаково в обох режимах.

Після зміни режиму файли треба застосувати на RB4011 заново (див. [Застосування файлів](#застосування-файлів)), а клієнти, збережені під старими назвами, треба підключити до нової.

## Канали 5 ГГц без DFS

На 5 ГГц частина каналів потребує DFS (захисту від радарів). Радіо на такому каналі після кожного запуску мусить 1 хвилину (на каналах приблизно 5600-5650 МГц до 10 хвилин) слухати ефір, і весь цей час мережі 5 ГГц не видно. Якщо радіо виявить радар, воно ще й змінить канал.

Тому в шаблоні є профіль каналу, який пропускає DFS-канали:
```
/interface wifi channel add name=ch-5g skip-dfs-channels=all
```
Його використовує конфігурація `cfg-5g`: це радіо точок доступу (через CAPsMAN) і власне радіо RB4011. Конфігурація 2.4 ГГц (`cfg-2g`) не змінюється, бо там DFS немає.

- Це налаштовується лише на RB4011, у файлах точок доступу нічого немає.
- Каналів стає менше (зазвичай 36-48 і, якщо дозволяє країна, 149-165), тому сусідні точки можуть частіше ділити один канал. Натомість мережа з'являється одразу.
- Ширину каналу й стандарт (`band`) у профілі свідомо не задано. `band=5ghz-ac` утримував би ax-радіо hAP ax3 на швидкостях Wi-Fi 5, а за замовчуванням радіо саме обирає найкращі параметри.
- Я не перевіряв цей профіль на реальному пристрої. Якщо `skip-dfs-channels` відхиляється, подивіться допустимі значення: `/interface wifi channel add ?`. М'якший варіант `skip-dfs-channels=10min-cac` пропускає лише канали з 10-хвилинною перевіркою.
- Щоб застосувати на працюючому RB4011 без скидання:
  ```
  /interface wifi channel add name=ch-5g skip-dfs-channels=all
  /interface wifi configuration set cfg-5g channel=ch-5g
  ```
  Якщо ви застосовували попередню версію файла, замість `cfg-5g` може бути `cfg-main`: `/interface wifi configuration print` покаже поточні імена.

## Випадкові значення Wi-Fi

```
python3 randomize.py                              # нові WIFI_PASSWORD і суфікс WIFI_SSID
python3 randomize.py --admin-password             # те саме + новий ADMIN_PASSWORD
python3 randomize.py --password-length 24         # паролі довжиною 24 символи
python3 randomize.py --dry-run                    # лише показати значення, файл не змінювати
python3 generate.py                               # оновити файли налаштувань
```

| Параметр | Опис |
|---|---|
| `--admin-password` | Також згенерувати новий `ADMIN_PASSWORD`. Без нього `ADMIN_PASSWORD` не змінюється. |
| `--password-length N` | Довжина згенерованих паролів, від 8 до 63. За замовчуванням 16. |
| `--dry-run` | Показати нові значення, не змінюючи `.env`. |
| `--env ШЛЯХ` | Інший файл замість `.env`. |

- `WIFI_PASSWORD` стає випадковим паролем. Кожен згенерований пароль (і Wi-Fi, і admin) містить щонайменше одну цифру, одну малу літеру, одну велику літеру та один спецсимвол.
- Спецсимволи: `! @ % ^ & * - _ + = . , : ~`. Їх підібрано так, щоб вони не ламали `.env`, рядки RouterOS і копіювання в термінал (тому немає лапок, `$`, `?`, `\`, `#`, пробілів).
- Максимальна довжина **63 символи** — це обмеження WPA2/WPA3-PSK на пароль Wi-Fi. Вона діє для обох паролів, щоб вони завжди мали однакову довжину.
- З параметром `--admin-password` скрипт також замінює `ADMIN_PASSWORD`. Новий пароль виводиться в консоль, збережіть його: на роутерах він з'явиться лише після повторного застосування файлів.
- Останні **4 символи** `WIFI_SSID` замінюються випадковим 4-значним шістнадцятковим числом (цифри 0-9 і великі літери A-F), як у назвах мереж TP-Link: `Tp-Link_0000` стає, наприклад, `Tp-Link_7D15`. Префікс залишається таким, як у `.env`. Якщо SSID закінчується не суфіксом, а чимось іншим, цей хвіст теж буде замінено.
- Решта `.env` (коментарі, кількість пристроїв, країна) не змінюється, а `ADMIN_PASSWORD` змінюється лише з `--admin-password`. Файл записується через тимчасовий, тож обрив посеред запису його не пошкодить.
- Значення беруться з криптографічного генератора випадкових чисел Python (`secrets`).
- Після зміни пароля й SSID файли на пристроях треба застосувати заново (див. [Застосування файлів](#застосування-файлів)), а клієнтам ввести нові дані. Скрипт змінює лише `.env`, а не роутери.

## Пакет Wi-Fi для hAP ax3

hAP ax3 працює на пакеті **`wifi-qcom`** (не `wifi-qcom-ac`), це підтверджує [документація MikroTik](https://manual.mikrotik.com/docs/wireless/wifi/). Чи вшитий він у прошивку з заводу, документація прямо не каже. Тому перевіряйте на самому пристрої:

1. Підключіть пристрій і виконайте `/system package print`.
2. Якщо `wifi-qcom` є і не позначений `X`, налаштовувати нічого не треба.
3. Якщо його немає або він вимкнений:
   - Вимкнений (`X`): `/system package enable wifi-qcom`, потім `/system reboot`.
   - Відсутній: завантажте з [mikrotik.com/download](https://mikrotik.com/download) Extra packages для **ARM64** тієї ж версії, що й `routeros` на пристрої, розпакуйте `wifi-qcom-<версія>-arm64.npk`, завантажте його через Files, виконайте `/system reboot`. Якщо пакет після цього вимкнений, увімкніть його й перезавантажте ще раз.
4. Пакет `wireless` для ax3 не потрібен.

Якщо перевстановлюєте RouterOS через Netinstall, встановлюйте разом із основним пакетом і `wifi-qcom`: інакше Wi-Fi інтерфейсів не буде. Використовуйте блок живлення з комплекту: на [форумі MikroTik](https://forum.mikrotik.com/t/hap-ax3-netinstall-wifi-qcom-solved/263055) описаний випадок, коли слабкий блок не давав пристрою завантажитися під час ініціалізації Wi-Fi.

## Резервна копія

Скидання конфігурації стирає все, тому перед ним збережіть поточні налаштування кожного пристрою:

```
/export show-sensitive file=backup-rb4011
```

- Підставте ім'я пристрою: `backup-ac3-1`, `backup-ax3-2` тощо. Команда створює файл `backup-<ім'я>.rsc` у Files на роутері.
- Параметр `show-sensitive` додає в експорт паролі, ключі й інші секрети у відкритому вигляді. Без нього RouterOS 7 їх приховує, і з такої копії пароль не відновити.
- Завантажте файл на комп'ютер: WinBox (Files, перетягнути) або `scp admin@<адреса>:backup-rb4011.rsc backups/`. Каталог `backups/` додано в `.gitignore`.
- Файл містить паролі, тому не публікуйте його, не надсилайте й не комітьте.
- Відновлення: завантажте файл на скинутий роутер і виконайте `/import file-name=backup-rb4011.rsc`. Експорт у вигляді скрипта найкраще відновлюється на тому самому пристрої з тією ж версією RouterOS. Я цього не перевіряв.
- За потреби можна зробити ще й бінарну копію (`/system backup save name=backup-rb4011`). Вона відновлюється через `/system backup load`, але лише на тому самому пристрої.

## Застосування файлів

Скрипти призначені для щойно скинутого роутера і не є ідемпотентними. Повторний запуск завершиться помилками через дублікати записів.

1. Збережіть резервну копію, див. [Резервна копія](#резервна-копія).
2. Завантажте `.rsc` файл пристрою в кореневий каталог файлів роутера (WinBox: Files, перетягнути; або `scp generated/ac3-1.rsc admin@<адреса>:`).
3. Скиньте роутер і запустіть файл після скидання:
   ```
   /system reset-configuration no-defaults=yes skip-backup=yes run-after-reset=ac3-1.rsc
   ```
4. Дочекайтеся перезавантаження. Скрипт виконується при першому запуску.

Скидання стирає IP-конфігурацію роутера, тому за потреби підключайтеся через MAC-WinBox (або кабелем зі статичною адресою). RB4011 буде доступний за адресою `192.168.89.1` після виконання скрипта. Пакети Wi-Fi після скидання лишаються.

Якщо скрипт зупинився посередині, усе до рядка з помилкою залишається застосованим. Помилку дивіться в `/log print`.

### Порядок

Спочатку налаштуйте RB4011, потім точки доступу. Порядок не критичний, але так усе проходить найгладше:

- Точка доступу отримує адресу керування від DHCP-сервера на RB4011 і знаходить контролер CAPsMAN через міст, тому обидва пристрої мають працювати.
- Якщо налаштувати точку першою, нічого не зламається. Її скрипт не залежить від RB4011. Коли RB4011 запрацює, точка має сама отримати адресу й приєднатися; це може зайняти хвилину-дві. Витягніть і знову вставте кабель, щоб прискорити.
- Підключайте кожну точку до LAN-порту RB4011 (ether2-10 або SFP+), ніколи до ether1 (WAN).
- Точку можна скинути з відключеним кабелем і підключити його після завершення скрипта на RB4011.
- Після приєднання точка з'являється в `/interface wifi capsman remote-cap print` на RB4011, а динамічні інтерфейси `cap-wifi` втрачають прапорець `X` (вимкнено).

### Додати або перегенерувати пристрої

Змініть `AC3_COUNT` або `AX3_COUNT` у `.env` і знову запустіть `python3 generate.py`. Старі файли в `generated/` видаляються й створюються заново. Налаштовуйте скриптом лише нові пристрої, на вже працюючих повторно його не запускайте.

## Моніторинг трафіку

Скрипт [traffic.py](traffic.py) показує, до якої точки доступу (RB4011, ac3, ax3) підключений кожен пристрій і яке навантаження він створює. Він за один SSH-сеанс виконує на RB4011 лише команди читання, двічі знімає лічильники байтів з паузою між зрізами й рахує швидкість як різницю:

```
python3 traffic.py                  # 30 секунд
python3 traffic.py --duration 60
python3 traffic.py --show-zeros     # з клієнтами без трафіку
python3 traffic.py --max-only       # топ-10 клієнтів за TX
```

Приклад результату (скорочено):
```
ax3-1 (192.168.89.168)
  порт ROUT до точки: TX 590.3kbps, RX 8.4Mbps
  Wi-Fi клієнтів: 26, разом TX 706.8kbps, RX 9.6Mbps
    Пристрій        IP              Діапазон  Сигнал         TX        RX
    iPhone          192.168.89.143  5ghz-ax   -66     241.0kbps   9.5Mbps
```

- Параметри: `--host` (за замовчуванням `192.168.89.1`), `--user` (`admin`), `--duration` (секунди, 1-300, за замовчуванням 30), `--show-zeros` (за замовчуванням клієнти з TX і RX 0bps приховані, лишається рядок з їх кількістю), `--source ТОЧКА` (з `--max-only`: лише клієнти цієї точки), `--client-mac MAC` (статистика лише по цьому клієнту, показується навіть без трафіку), `--max-only` (одна таблиця з 10 клієнтами з найбільшим TX, колонка «Точка» показує, до чого підключений клієнт), `--raw ФАЙЛ` (зберегти сирий вивід роутера), `--input ФАЙЛ` (розібрати збережений вивід без роутера).
- Пароль SSH запитує сам `ssh`. Щоб не вводити його щоразу, завантажте на роутер публічний ключ: `/user ssh-keys import public-key-file=id_ed25519.pub user=admin`. Налаштування роутера скрипт не змінює.
- `TX`: від точки до пристрою (завантаження на пристрій), `RX`: від пристрою до точки (вивантаження з пристрою). Швидкості в бітах за секунду, середні за час вимірювання.
- До якої точки належить Wi-Fi клієнт, визначається за радіо `cap-wifiN` у таблиці `/interface wifi registration-table`: коментар до нього вказує MAC точки. Клієнти власного радіо RB4011 (`wifi1`) показані під `rb4011`.
- Рядок «порт ... до точки» це лічильники порту RB4011, до якого підключена точка: весь трафік точки, зокрема дротових пристроїв за нею. Окремих лічильників для дротових клієнтів немає, тому вони лише перелічені (їх видно за MAC на порту точки).
- Імена пристроїв беруться з DHCP-оренди; якщо hostname порожній, показується MAC (так буває для пристроїв з випадковою MAC-адресою).

### Живий режим

[live.py](live.py) показує те саме, що `traffic.py --max-only`, але постійно оновлює таблицю на місці:

```
python3 live.py                  # оновлення кожні 5 с, топ-10
python3 live.py --interval 3 --top 15
python3 live.py --source ax3-1   # лише клієнти однієї точки
python3 live.py --client-mac AA:BB:CC:DD:EE:FF   # лише один клієнт
```

- Параметри: `--host`, `--user`, `--interval` (пауза між оновленнями, 2-60 с, за замовчуванням 5), `--top` (скільки клієнтів показувати), `--source` (лише клієнти однієї точки: `rb4011`, `ac3-1`, `ax3-2` тощо, регістр не важливий; невідому назву скрипт відхиляє й називає доступні), `--client-mac` (лише клієнт з цією MAC-адресою; двокрапки чи дефіси, регістр не важливий; якщо його немає серед підключених, скрипт пише про це й чекає), `--count` (зупинитися після N оновлень, 0 = без обмеження). Вихід: `Ctrl+C`.
- Одне SSH-з'єднання використовується повторно, тому пароль запитується один раз, а кожне оновлення лише читає дані (`print`). Швидкість рахується між двома сусідніми зрізами за годинником роутера.
- Дані при короткому інтервалі «стрибають»: це миттєва швидкість за кілька секунд, а не середнє. Для стабільнішої картини збільшіть `--interval`.
- Перший екран з'являється після другого зрізу, тобто через `--interval` секунд.

### Скрипти на самому роутері

Ті самі звіти можна запускати прямо на RB4011, без комп'ютера і Python. Скрипти лише читають дані й нічого не змінюють.

| Файл | Функція | Аналог |
|---|---|---|
| [routeros/mesh-traffic.rsc](routeros/mesh-traffic.rsc) | `$meshTraffic` | `traffic.py` |
| [routeros/mesh-traffic-max.rsc](routeros/mesh-traffic-max.rsc) | `$meshTrafficMax` | `traffic.py --max-only` (тут це поведінка за замовчуванням) |
| [routeros/mesh-live.rsc](routeros/mesh-live.rsc) | `$meshLive` | `live.py` |
| [routeros/mesh-client.rsc](routeros/mesh-client.rsc) | `$meshClient` | немає: миттєвий зріз без вимірювання (точка, сигнал, TX/RX зараз) |
| [routeros/mesh-rejected.rsc](routeros/mesh-rejected.rsc) | `$meshRejected` | немає: пристрої, відключені через access-list (час, MAC, ім'я, точка, сигнал) з логу роутера; з `all=yes` додається колонка причини. Параметри: `last`, `all=yes`, `clientMac`. Обмеження описані на початку файлу: у логу немає причини `min-signal`, лише `access-list changed`. |

**Як користуватися.** Завантажте потрібний файл на роутер (WinBox: Files, перетягнути) і виконайте в терміналі:

```
/import file-name=mesh-traffic-max.rsc
$meshTrafficMax
$meshTrafficMax duration=60 source=ax3-1
$meshTrafficMax clientMac=AA:BB:CC:DD:EE:FF
```

Імпорт (і `/system script run`) лише визначає функцію, яку потім викликають з параметрами. Після перезавантаження роутера глобальні функції зникають, тому файл імпортують знову. Щоб не завантажувати файл повторно, збережіть його як скрипт: `/system script add name=mesh-traffic-max source=[/file get mesh-traffic-max.rsc contents]`, і після перезавантаження достатньо `/system script run mesh-traffic-max`.

**Параметри** (усі необов'язкові; імена без дефісів, бо їх не допускає RouterOS):

| Параметр | Скрипти | Значення |
|---|---|---|
| `duration` | `$meshTraffic`, `$meshTrafficMax` | Тривалість вимірювання, 1-300 с (за замовчуванням 30). |
| `showZeros` | `$meshTraffic` | `yes` показує й клієнтів з TX і RX 0bps (за замовчуванням вони приховані). |
| `source` | `$meshTrafficMax`, `$meshLive` | Лише клієнти однієї точки: `rb4011`, `ac3-1`, `ax3-2` тощо. |
| `clientMac` | усі чотири | Лише клієнт з цією MAC-адресою. |
| `interval` | `$meshLive` | Пауза між оновленнями, 2-60 с (за замовчуванням 5). |
| `top` | `$meshLive` | Скільки клієнтів показувати (за замовчуванням 10). |
| `count` | `$meshLive` | Зупинитися після стількох оновлень (0 = до Ctrl+C). |

- Живий режим зупиняється `Ctrl+C`. Для оновлення на місці потрібен термінал з підтримкою ANSI (SSH, WinBox-термінал).
- Текст виводу й коментарі в цих файлах англійською і лише ASCII: термінал RouterOS відкидає не-ASCII символи в скриптах. Назви пристроїв і портів, які приходять з роутера (наприклад, порт `Зал`), показуються як є.
- Розрахунок такий самий, як у Python-версії: швидкість це приріст лічильників між двома зрізами за годинником роутера. Скрипт виконується на роутері, тому вимірювання трохи навантажує процесор (кілька сотень запитів на зріз).

## Перевірка

На RB4011:

```
/ip dhcp-client print                       # ether1 bound
/ping 1.1.1.1 count=3
/interface wifi capsman print               # enabled: yes
/interface wifi capsman remote-cap print    # кожна точка у списку, state Ok
/interface wifi radio print                 # локальне радіо плюс два радіо на кожну точку
/interface wifi print                       # wifi1 (власне радіо), cap-wifi1, cap-wifi2 ... без прапорця X
/interface bridge port print                # wifi1 є портом моста на RB4011 (може бути динамічним)
/interface wifi registration-table print    # підключені Wi-Fi клієнти
/ip service print                           # увімкнені лише ssh і winbox
```

На точці доступу:

```
/ip dhcp-client print                       # bridge bound, 192.168.89.x
/interface wifi cap print                   # enabled: yes
/interface wifi print                       # радіо більше не вимкнені
/interface bridge port print                # wifi1 і wifi2 є портами моста
/log print where topics~"wifi"
```

## Усунення несправностей

| Симптом | Причина / рішення |
|---|---|
| `generate.py` пише помилку | Виправте `.env` за текстом помилки. Типові причини: порожній параметр, пароль зі значенням-прикладом, пароль Wi-Fi коротший за 8 символів. |
| Скрипт зупинився з помилкою `bad parameter` або подібною | Рядок із помилкою і все після нього не виконані. Дивіться `/log print`, виправте шаблон і застосуйте скрипт заново на скинутому роутері. |
| `capsman print` показує `enabled: no`, а configuration/provisioning/security порожні | Імпорт зупинився до секції Wi-Fi. Перегляньте `/log print` і виконайте пропущені рядки. |
| Точка є в `remote-cap`, але радіо немає в `/interface wifi radio print` | Радіо точки вимкнені або не передані CAPsMAN. На точці: `/interface wifi set [find] configuration.manager=capsman disabled=no` (вже є в шаблоні). |
| `cap-wifi1/2` з'явилися, але лишаються вимкненими (`X`) | Правила provisioning не підходять під діапазони радіо. Правило підходить лише радіо, яке підтримує всі вказані діапазони. Перевірте `/interface wifi radio print detail`: потрібні діапазони `2ghz-n` та `5ghz-ac`. Правила в шаблоні написані так, щоб підходити і ac3, і ax3, але на ax3 це не перевірялося. |
| Клієнти підключаються до Wi-Fi, але не отримують DHCP-адресу / немає інтернету, а дротові клієнти працюють | Радіо точки не є портами моста. Перевірте `/interface bridge port print` на точці: `wifi1` і `wifi2` мають бути в списку (вже є в шаблоні). Якщо їх немає: `/interface bridge port add bridge=bridge interface=wifi1` і так само для `wifi2`. |
| Старий пристрій (розумна розетка, лампа, принтер) не підключається до єдиної мережі | Часто це 2.4 ГГц пристрій, який не підтримує WPA3 або швидкий роумінг 802.11r. Згенеруйте окремі мережі: `python3 generate.py --show-separate`, і підключіть його до мережі 2.4 ГГц. |
| Власне радіо RB4011 (`wifi1`) не роздає мережу, у `/interface wifi print` написано "SSID not set" | Радіо не отримало конфігурацію. Виконайте: `/interface wifi set wifi1 configuration=cfg-5g configuration.manager=local disabled=no`. |
| Wi-Fi 5 ГГц не видно, у `/interface wifi print` написано "DFS channel availability check" | Радіо обрало DFS-канал і мусить спочатку 1 хвилину (на каналах приблизно 5600-5650 МГц до 10 хвилин) перевіряти ефір на радари. У шаблоні це вже обходиться профілем `ch-5g` (див. [Канали 5 ГГц без DFS](#канали-5-ггц-без-dfs)). Якщо повідомлення все ж з'явилося, перевірте `/interface wifi channel print` і що `cfg-5g` має `channel=ch-5g`. |
| Клієнти підключаються до `wifi1` на RB4011, але не отримують DHCP-адресу | Перевірте `/interface bridge port print`: `wifi1` має бути портом моста (можливо динамічним). Якщо його немає: `/interface bridge port add bridge=bridge interface=wifi1`. Якщо радіо RB4011 не потрібне, рядок у кінці [шаблону](templates/rb4011.rsc.tpl) можна видалити. |
| Точка не приєднується | Різні версії RouterOS, відсутній пакет Wi-Fi або точка не в тому самому мості/LAN, що й RB4011. |
| На ax3 немає Wi-Fi інтерфейсів | Не встановлений або вимкнений пакет `wifi-qcom`, див. [Пакет Wi-Fi для hAP ax3](#пакет-wi-fi-для-hap-ax3). |

## Примітки

- Власне радіо RB4011 (`wifi1`) теж роздає мережу: воно налаштовується напряму тією самою конфігурацією `cfg-5g` у режимі `configuration.manager=local`, а не через CAPsMAN. Режим `capsman-or-local` не підключав радіо до власного CAPsMAN: у `/interface wifi print` було "no connection to CAPsMAN, managed locally; SSID not set". Це радіо працює лише на 5 ГГц (діапазони `5ghz-a/n/ac`, Wi-Fi 5), мережі 2.4 ГГц від RB4011 немає. Рядок стоїть у кінці [шаблону](templates/rb4011.rsc.tpl), і я не перевіряв його на реальному пристрої.
- Файрвол: RB4011 приймає вхідний трафік лише з LAN і для встановлених з'єднань, нові з'єднання з WAN блокуються. Усі сервіси, окрім SSH і WinBox, вимкнені, а neighbor discovery і MAC-сервер обмежені LAN.
- Шаблони містять українські коментарі. RouterOS ігнорує коментарі, але після першого скидання перевірте `/log print where topics~"error"`: якщо там помилка через символи, замініть коментарі в шаблонах на англійські.
